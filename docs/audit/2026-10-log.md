# Audit digest — 2026-10

Monthly digest of **short** audit entries (≤ ~40 lines). Longer entries keep their own
`docs/audit/<date>-<slug>.md` file. Append-only: add a new `## <YYYY-MM-DD> — <title>` section at the
end; never edit an old one — correct it with a new section that `**Supersedes:**` it.

## 2026-10-05 — Audit process: IR search, monthly digests, Status/Supersedes

**Status:** Active

### Prompt
After the architecture review the user asked whether the audit trail improves quality and chose three
improvements: (1) retrieve audit entries with NLP information retrieval, (2) merge short detail files,
(3) add Status/Supersedes. No UI/GitHub rendering — plain Markdown + CLI only.

### Decision
1. **Retrieval:** `scripts/audit-search.js` — BM25 over `docs/audit/` (tokenise, stop-words, light stem,
   title boost, CODE tokens kept whole). `--scope all` also searches todo/fix-log/notes. A
   `--hook` mode (UserPromptSubmit) prints the top active hits as context. **Not wired** — editing hook
   config needs the user (see `.claude/rules/tracking-files.md`).
2. **Merge:** entries ≤ ~40 lines go in `docs/audit/<YYYY-MM>-log.md` as `## ` sections; longer ones keep
   their own file. Existing files are untouched (append-only), so the rule applies going forward.
3. **Status/Supersedes:** each entry carries `**Status:** Active | Superseded by <ref>`; a correcting
   entry adds `**Supersedes:** <ref>[, <ref>]` (file basename or heading substring). The search script
   derives superseded entries from `Supersedes:`, so old entries are never edited. Superseded hits are
   hidden unless `--all-status`.

### Limits (honest)
BM25 is lexical: it does not translate (a Vietnamese query will not match English entries) and has no
semantic embedding. Good enough at ~15 entries; revisit if the corpus grows past a few hundred.

## 2026-10-05 — Audit retrieval engine: Whoosh replaces the hand-written BM25 script

**Status:** Active

This amends item 1 ("Retrieval") of "Audit process: IR search, monthly digests, Status/Supersedes";
items 2–3 of that entry stand.

### Findings
Top-1 agreed on 8/10 queries; Whoosh ranked the right entry first on the key query where the JS
version ranked it second. Both missed `anlz-05` vs `anlz05` (code-token normalisation, not a library

### Decision

replaces `audit-search.js`. Kept: digest chunking, Status/Supersedes, `--scope all`, `--all-status`,
`--hook`. Added: on-disk index in git-ignored `.cache/audit-index/` rebuilt when any source file's
mtime/size changes; joined task-code tokens (`anlz-05` also indexed/queried as `anlz05`);
`scripts/requirements.txt`. Query is plain text (Whoosh syntax such as `field:` deliberately not exposed).
Hook default `--min-score 12` (BM25F scale differs from the JS score; tunable).

### Reasoning
User preference for a real IR library; accepted cost: a Python dependency in a repo whose other scripts
are Node. Rejected: keeping both (two sources of truth).

### Verification
`anlz-05 stray move` now returns the anlz05 misdiagnosis entry at rank 1; Supersedes hides/reveals
correctly (temp file, removed); index reused on second run; `--hook` prints hits only above threshold.

## 2026-10-08 — PAL-01 benchmark: C++ palette search vs Whoosh baseline

**Status:** Active

### Prompt
Compare our classical-NLP palette search (Model A) with a Python 3.13 Whoosh baseline (Model B) on one shared dataset: accuracy and performance (agreed in the command-palette design, 2026-10-08).

### Findings
Test split, 98 queries over 61 real entries (`python3.13 scripts/palette_bench.py --split test`): MRR A 0.980, B (Whoosh + same pre-tokenizer/lexicon) 0.950, B-stock 0.719; recall@3 0.990 / 0.959 / 0.755. Paired bootstrap MRR A−B = +0.031, 95% CI +0.003…+0.066. Stock Whoosh collapses on no-diacritic (0.20) and typo (0.32) queries — the fold/phrase/fuzzy stages carry the Vietnamese support. B loses on transposition typos (Whoosh `FuzzyTerm` has no transposition). Latency p50: A 3 µs, B ~1 ms; build 1.75 ms vs 29 ms (in-process, warm; not a quality signal).

### Reasoning
Caveats: dataset and lexicon are author-written and the corpus is only 61 entries, so absolute numbers are optimistic; the lexicon was authored from entry vocabulary, with two dev-set tweaks (removed `search` from the analyze synonym group; 0.9× penalty for `!` commands when `!` not typed); no tuning on the test split. Whoosh is a dev-only baseline (needs `python3.13` without `-I`).

### Knowledge
SKILLS_TREE `nlp-semantic-search-embeddings` (keep BM25 baseline, evaluate on own queries), `nlp-vietnamese-multilingual` (NFC, fold with care).

### Decision
PAL-01 done (PR #56). Not built: synthetic scale corpus for latency; queries total 199 (target 200+). Follow-ups: PAL-02 (overlay + registries), PAL-03 (settings registry).
