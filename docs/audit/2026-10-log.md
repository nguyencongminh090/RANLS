# Audit digest — 2026-10

Monthly digest of **short** audit entries (≤ ~40 lines). Longer entries keep their own
`docs/audit/<date>-<slug>.md` file. Append-only: add a new `## <YYYY-MM-DD> — <title>` section at the
end; never edit an old one — correct it with a new section that `**Supersedes:**` it.

## 2026-10-05 — Audit process: IR search, monthly digests, Status/Supersedes

**Status:** Active

### Prompt
After the architecture review the user asked whether the audit trail improves quality and chose three
improvements: (1) retrieve audit entries with NLP information retrieval, (2) merge short detail files,
(3) add Status/Supersedes. No UI/GitHub rendering — plain Markdown + CLI only.

### Decision
1. **Retrieval:** `scripts/audit-search.js` — BM25 over `docs/audit/` (tokenise, stop-words, light stem,
   title boost, CODE tokens kept whole). `--scope all` also searches todo/fix-log/notes. A
   `--hook` mode (UserPromptSubmit) prints the top active hits as context. **Not wired** — editing hook
   config needs the user (see `.claude/rules/tracking-files.md`).
2. **Merge:** entries ≤ ~40 lines go in `docs/audit/<YYYY-MM>-log.md` as `## ` sections; longer ones keep
   their own file. Existing files are untouched (append-only), so the rule applies going forward.
3. **Status/Supersedes:** each entry carries `**Status:** Active | Superseded by <ref>`; a correcting
   entry adds `**Supersedes:** <ref>[, <ref>]` (file basename or heading substring). The search script
   derives superseded entries from `Supersedes:`, so old entries are never edited. Superseded hits are
   hidden unless `--all-status`.

### Limits (honest)
BM25 is lexical: it does not translate (a Vietnamese query will not match English entries) and has no
semantic embedding. Good enough at ~15 entries; revisit if the corpus grows past a few hundred.

## 2026-10-05 — Entry templates: Scope + Reasoning + Knowledge

**Status:** Active

### Prompt
User asked to improve the templates and proposed Scope + Reasoning + Knowledge.

### Findings
Only `todo` had a template (inside `/sprint add-task`), and it was bypassed when ARCH-01..03 were
hand-written. Status wording varied (`✅ DONE (Active…`, `✅ FIXED`, …), long result narratives sat in
todo Status blocks (duplicating fix-log), `Related` (38×) duplicated `Depends on`, and fix-log/audit
headings were inconsistent.

### Decision
- `docs/templates/{todo,fix-log,audit}.md` are the single source; `/sprint add-task` now points at
  `todo.md`. Added **Reasoning** (why + rejected alternatives) and **Knowledge** (cite
  `docs/knowledge/`, skills, audits) beside the existing Scope/Scope boundary/Acceptance.
- `Status:` is a one-line closed set; Priority has criteria (P1 blocks/corrupts, P2 workaround, P3 cleanup).
- `scripts/check-task-structure.js` lints **open** todos (first Status line OPEN/ACTIVE) for required
  sections; closed legacy files are not re-linted. Negative test (open file missing sections) fails as expected.
- fix-log: Reasoning not required (Root cause + Fix cover it); Knowledge optional.

### Not done
No hook wiring; no migration of old files; fix-log/audit templates are not machine-linted.

## 2026-10-05 — Task-size classification (S/M/L): small tasks get a temp note, not an audit

**Status:** Active

### Prompt
User: add task classification; small/small-scope tasks get a temporary note — better than auditing every task.

### Decision
S/M/L table in `.claude/rules/tracking-files.md` (+ `CLAUDE.md` pointer, `docs/templates/note.md`).
S → expiring note; M → todo, audit only for a real decision; L → feature folder + todo + audit.
Bug fixes always get a fix-log. Unsure → larger size. `/sprint close` triages expiring notes.

### Reasoning
Auditing everything buries the decisions that matter and degrades BM25 retrieval; the size test uses
reversibility and layer/protocol/format/process impact, the same criteria that made past audits useful.
Rejected: a numeric line-count threshold alone (misses small-but-architectural changes).

### Knowledge
`docs/knowledge/quality-tradeoff-analysis.md`.

### Not done
No lint of notes' `Expires`; classification is judgment, not enforced.
